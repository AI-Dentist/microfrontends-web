# Operational machine learning

Appointments display the backend's `nivelRiesgo` (BAJO/MEDIO/ALTO), `probabilidadNoShow` percentage and `accionRecomendada`. The high-risk filter matches only `ALTO`; the frontend never recomputes the backend thresholds (0.65 remains MEDIO). GET `/api/agendamiento/citas` enriches each appointment; `data.mlDisponible=false` keeps the agenda usable with explicit missing-prediction copy.

GET `/api/agendamiento/ml/clusters` populates patient distribution and per-patient assignments in citas, and rotation badges beside minimum-stock alerts in stock. The exact envelope is `data.pacientes` / `data.insumos`, each with `centroides`, `distribucion` and `asignaciones`; assignment keys are `paciente_id` / `insumo_id` and `cluster`. Labels are shown verbatim, including Frecuente y Puntual, Riesgo de Abandono / Inconstante, Atención Esporádica / Urgencias and Alta Rotación Crítica, Consumo Estándar, Baja Rotación. `datosSinteticos` is disclosed. Missing clusters never imply a low-risk classification and a sidecar 503 does not prevent appointment/stock use.

The additive client also exposes `predictNoShow(payload)` using POST `/api/agendamiento/ml/predict-noshow` (e.g. `{cita_id}`), preserving `featuresImputadas` from the response. Normal list enrichment means the UI does not need extra per-row inference calls. All ML requests use the same Gateway client and current Shell Bearer token. Standalone defaults now use `/api/agendamiento`, with Vite forwarding `/api` to the local Gateway (port 80), not MS3's private port. No appointment/stock idempotency or offline logic changes.
